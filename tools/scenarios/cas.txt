# Create-a-Sim (~11 min, frame 13710 at the end; lane JH): the CAS smoke scenario, for the CAS services (cTSCASSystem, cTSCASBodyPartSystem,
# the skin, bin, pattern and material catalogs) and the nTSUICAS components.
# Boot and load Belladonna Cove (frame-anchored host clicks, as load-check), open the Families bin and press
# "Create New Family": that enters CAS. There: Create A Sim; step 1 Randomize, Female, Teen then Adult (age changes),
# skin tone 3, both fitness types, first name typed; step 2 a premade head; step 3 a hair colour and style, a full-face
# archetype, a nose archetype, Undo and Redo; step 4 the glasses and makeup tabs; step 5 an everyday outfit, the formal
# category and an outfit there; step 6 an aspiration, a zodiac sign, two turn-ons and a turn-off (DONE refuses without
# the aspiration and the turn-ons); DONE (Accept Sim);
# family name typed; Accept Family, back to the neighbourhood; then the game's own quit (exit code 0 expected).
# Every input is a host click at a fixed framework tick or a posted message (type: posts WM_CHAR), so it runs quiet.
#
# Passes when the window tree taken after Accept Family is the neighbourhood's (under 1000 windows; CAS has ~2100) and
# the game quits by itself. Screenshots are blank in quiet mode: the window trees are the record of a failed run
# (local/saves/<stamp>-cas.ts2wintree.txt, one block per stage, with captions: the first name shows in the editor's
# window 0x2cb7b3d6, a refusal as a cTSWinPictureDialog with its text). Coordinates and ids come from those trees and
# the game's UI scripts: client pixels = UI x 2560/1738, y 1360/924; the CAS 1024x768 layout sits at the bottom left
# (UI y + 156), step panels hang from the sub panel anchor (UI 583,918). Run with -ResetUserData -Quiet [-Reference].
